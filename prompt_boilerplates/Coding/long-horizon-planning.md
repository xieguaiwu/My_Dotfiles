# Long-Horizon Planning — 超长任务愿景与进度管理

## 核心理念

**长期任务中的每个 agent 都必须知道自己在整幅地图的哪个位置，并让别人也知道。**

多日、多会话、多 agent 协作的项目里，最大的风险不是单个任务失败，而是**方向漂移**——每个 agent 都在完成自己手里的任务，但没人清楚这些任务服务于什么终局，做到了哪一步。本 skill 用一份 `VISION.md` 把三件事制度化：

1. **短期、中期、长期要求**——三档目标明确写在文档里，每个 agent 进入时声明自己的任务属于哪一档
2. **愿景规划**——长期目标从愿景声明逐层分解而来，每档目标有完成标准
3. **完成进度声明**——完成长期规划的任何一部分，必须在文档和报告里明确说明（完成了第几阶段、第几步、还剩什么），让用户和其他 agent 无需追问即可理解

> 核心原则：**未声明位置的任务 = 方向不明的任务；未记录进度的完成 = 未发生的完成。**
> 本 skill 是 `project-documentation-protocol.md` 在时间维度上的特化：文档协议解决"当前状态是什么"，本 skill 解决"当前状态在长期规划中的位置"。

---

## 适用场景

- 预计跨多日/多会话/多 agent 协作的项目（如 ML 训练流水线、量化研究、大型迁移）
- 有明确终局愿景但需要分阶段推进的工作
- 多个 subagent 并行/接力执行，需要向用户和其他 agent 说明各自贡献的场景

**不适用**：单会话小任务（当天完成、<3 个独立步骤）——直接做，不创建 VISION.md；但若项目已有 VISION.md，仍需声明任务位置。

## VISION.md 文档规范

### 存放位置

```text
VISION.md   ← 项目根目录
```

### 三档时间标尺

默认按 `horizon_days`（7/30/90 天）划分，项目可自行调整并在 VISION.md 中注明：

| 档位 | 时间范围 | 回答的问题 | 典型粒度 |
|:---|:---|---|:---|
| **短期 S（Short）** | 本任务至 1 周 | 这次任务/本会话要完成什么 | 单次训练、单个功能、单轮实验 |
| **中期 M（Medium）** | 1 月至 1 个季度 | 当前推进中的阶段目标是什么 | 一个阶段（Phase）、一个里程碑 |
| **长期 L（Long）** | 季度及以上 | 项目最终要成为什么 | 愿景终点、终局状态 |

### 文档模板

```markdown
# VISION.md — 项目愿景与长期规划

> 维护规则：阶段推进时更新；每次工作完成后勾选进度；
> 本文件与 CONTEXT_FOR_NEXT_AGENT.md 的职责区分——
> CONTEXT 记录"当前状态"，VISION 记录"当前位置与去向"。

## 愿景声明（一句话）
{这个项目最终要达成什么状态。示例：} 
「VERSION2.5 突破框架：私有因子 + 判活闭环上线实盘，夏普稳定 > 2」

## 长期目标 L（愿景的分解）
- [ ] L1: {目标} —— 完成标准: {可验证的终点}
- [ ] L2: {目标} —— 完成标准: {可验证的终点}

## 中期目标 M（当前阶段）
- [ ] M1: {目标} —— 完成标准: {可验证的终点}
- [ ] M2: {目标} —— 完成标准: {可验证的终点}

## 短期目标 S（当前批次）
- [ ] S1: {目标}
- [ ] S2: {目标}

## 当前阶段与进度
- 当前阶段: 阶段 X/N（{阶段名}）
- 本阶段进度: 步骤 Y/Z
- 已勾选目标: L: 0/2 · M: 0/2 · S: 0/2
- 最近更新: YYYY-MM-DD

## 阶段衔接说明
- 阶段完成 → 勾选 + 记录「完成长期规划第 X/N 阶段」+ 日期
- 阶段终止/挂起 → 记录原因 + 复启条件（对齐 FALSIFICATION_SUMMARY.md）
- 下一步: {下一阶段的入口任务}
```

### 创建时机

| 情形 | 动作 |
|:---|:---|
| 项目预计跨多日/多会话，且无 VISION.md | 用模板创建（可并入 `project-documentation-protocol.md` §阶段C 的文档基础设施建立流程） |
| 项目已有 VISION.md | 直接阅读，不重建 |
| 单会话小任务 | 不创建；已有则按 §Agent 行为 声明位置 |

## Agent 行为约定

### 1. 进入任务时（强制声明）

任何 agent（含 subagent）在超长任务项目中开始工作前，**必须**：

1. 读 `VISION.md`（如存在；与 CONTEXT_FOR_NEXT_AGENT.md 同批阅读）
2. 在输出摘要/任务回复中声明三件事：

```text
本任务在长期规划中的位置:
  短期 S: {本任务完成什么}
  中期 M: {服务于哪个阶段目标，编号}
  长期 L: {愿景声明，一句话}
  当前进度: 阶段 X/N · 本阶段步骤 Y/Z
```

> 无 VISION.md 且任务预计跨会话 → 先创建 VISION.md 再声明（创建即声明）。
> 被派发的 subagent：在任务文本中由编排器给出上述定位，subagent 输出时复述。

### 2. 执行中（报告对齐）

- 中间报告/阶段汇报中，若涉及目标取舍，说明取舍与哪一档目标冲突（如"为赶中期目标 M2 跳过短期 S3"）
- 方向性决策（推翻/终止/新增阶段）必须记录到 VISION.md，不得只在对话里说

### 3. 完成时（进度声明，强制）

完成长期规划的任何一部分，**必须同时**：

1. 更新 `VISION.md`：勾选对应目标/步骤、推进阶段、更新「最近更新」日期
2. 在完成报告/提交消息中明确说明：

```text
完成长期规划: 第 X/N 阶段（{阶段名}）步骤 Y/Z ✅
  - 本次完成: {具体产出}
  - 对应目标: 中期 M{i} → 长期 L{j}（{L 的完成百分比}）
  - 剩余: {阶段 X 的剩余步骤 / 下一阶段入口}
```

> 这句话是给用户和其他 agent 的——不需要读完整对话历史就能知道项目推进到哪。

## 适用边界与豁免

本 skill 约束长期任务管理，非约束一切。以下情形可豁免或降级：

| 情形 | 处理 |
|:---|:---|
| 单会话小任务（当天完成、<3 步） | 不创建 VISION.md；项目已有则声明位置即可 |
| 探索性/spike（明确标注 throwaway） | 只记录观察，不更新 VISION.md 进度 |
| 用户明确要求不记录 | 用户指示优先 |
| 项目已有规划文档体系 | 沿用项目约定，本 skill 降级为参考（但完成进度声明仍建议保留） |
| 被派发 subagent 的中间结果 | 编排器负责汇总进度声明，subagent 只须在输出中复述定位 |

## 作业要求

```text
进入超长任务 → 读/建 VISION.md → 声明短/中/长期位置 → 执行 → 完成时更新进度 + 声明完成哪部分
```

1. 每个 agent 进入任务时必须声明：短期做什么、服务于哪个中期目标、属于哪个长期愿景
2. 项目必须有愿景规划（VISION.md 三档目标 + 愿景声明），缺失则先创建
3. 完成长期规划的任何一部分，必须更新 VISION.md 并在报告/提交消息中明确说明
4. 阶段终止/挂起必须记录原因与复启条件，防止后续 agent 在已终止方向上浪费
