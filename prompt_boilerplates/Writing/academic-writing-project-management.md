# 学术论文项目文档管理

经验源：《中介与剩余》项目（2026-03 至 2026-08，47 文件、10 核心文件、两轮方法论转向、三轮审稿回应）之实战沉淀。

## 任务目标

管理长线学术写作项目的文档体系。覆盖六事：目录结构、任务追踪、术语一致性、引用可信度分级、勘误留痕、归档纪律。使多文档协同的论文项目在数月乃至数年内可维护、可回溯、可交接。

## 核心认知（先读）

1. **正文唯一**：draft.md / main.tex 是唯一真源。支撑文档（形式化、演示、综述）头部标注「非论文正文，供引用」。
2. **归档不删除**：旧方案移 archive/，演化链完整保留。归档方案可复活，勿重复发明。
3. **术语是活的**：方法论转向后，旧术语必在支撑文档残留。统一须全局 grep + 逐处判定——本文用语换新，历史传统之引用（如 Windelband 段落）保留。
4. **引用有等级**：外部材料按承诺分级（✓ 已核 / △ 弱承诺 / ? 存疑）；证明按状态分级（定理 / 命题 / 观察）。本地无原书时，标注「基于标准文献解读，严格引用需核对原著」。
5. **勘误必留痕**：错误修正附勘误注记（日期 + 原误 + 正解 + 原因），防复发。
6. **编号会漂移**：tex 定义自动编号，中途插入定义则其后全部编号 +1，而配套 md 文档的硬编号引用不会自动跟。故新增定义一律追加至文档尾部；跨文档引用以**名称 + 章节**为主、编号为辅。
7. **归属必须核对原文**：概念出自何书何文，须核对本地藏书或可靠出处，勿凭印象归属（案例：「AE 层级」曾误归于 Alchourrón–Bulygin《Normative Systems》，实为 Hintikka 1988——两处「AE」同名异实，一为量词层级、一为规范系统之分）。

## 执行流程

### 1. 项目体检（audit 模式，进入项目时必做）

1. `read` todo.md → 掌握任务分层（A 正文 / B 桥接 / C 技术附录）、优先级与状态快照
2. `read` foundation.md（若有）→ 方法论地基、学术谱系、写作状态与风险
3. `bash` 盘点：现行文件 vs archive/ 文件数；核心文件是否不逾 10
4. `grep` 术语漂移：方法论转向后的旧术语（中/英/德文变体）在现行文件残留否
5. `grep` 编号一致性：tex 定义总数 vs 配套 md 引用的最大编号；tex 内部「Definition~N / §N」引用逐条核对
6. 输出体检报告（见输出格式）

### 2. 目录结构规范（restructure 模式）

标准结构（现行区 + 归档区）：

```text
项目根/
├── draft.md / main.tex      # 正文（唯一真源）
├── references.bib            # 唯一文献库（key 规范见 bib_key_naming.md）
├── literature_review.md      # 文献定位与新颖性声明
├── todo.md                   # 中央任务追踪
├── foundation.md             # 地基综述（长线项目/审稿准备时建）
├── formalization/            # 形式化支撑（每文件头标注「非论文正文」）
├── 评论与回复/                # 审稿材料（评论原文 + 逐点回应）
└── archive/                  # 归档演化链（按 structure/proposal/旧稿 分子目录）
```

重构时：现行文件移 archive/ 对应子目录，勿删；移毕 grep 跨文件引用，清理悬空引用。

### 3. 任务追踪纪律

todo.md 结构：优先级分层（A 正文 / B 桥接 / C 技术附录）+ 完成勾选 + 带日期状态快照 + 文档结构树。纪律：

- 一任务一行，动词开头；完成即勾选并注日期
- 重大转向（方法论/结构）在 todo 或 draft 头部带日期注记（例：「2026-06-27 诊断转向」）
- 新发现问题登记为 C 类或专设「已知问题」区，勿散落对话

### 4. 术语统一（terminology 模式）

1. `grep` 旧术语全部变体（中/英/德文、大小写、连写或分写）
2. 逐处判定：本文分类用语 → 替换；历史传统讨论之引用 → 保留原词
3. 首次替换处留一条括号注记（原称 XXWissenschaft）以存映射，其余直接替换
4. tex 内部编号引用失准处一并核查修正
5. 统一毕，`grep` 复扫归零（历史引用除外），报告残留清单

### 5. 引用可信度分级

| 分级对象 | 等级 | 含义 |
|---|---|---|
| 外部材料转述 | ✓ | 已核原文或可靠出处 |
| 外部材料转述 | △ | 概念可靠，具体表述/经验基础存疑，不承担论证 |
| 外部材料转述 | ? | 细节待核，仅作示意 |
| 数学断言 | 定理 | 完整证明 |
| 数学断言 | 命题 | 证明框架 / 部分证明 |
| 数学断言 | 观察 | 类比，明示非定理 |

补充纪律：方向性断言（先/后、因/果、过剩/短缺）必须回原文双向复核——凭记忆转述曾把「意义过剩」方向写反。

### 6. 勘误留痕（errata 模式）

格式：

```markdown
**勘误（YYYY-MM-DD）**：原误 X → 正解 Y。原因：Z。
```

勘误写入出错文档相应位置（勿另设文件），并在 index / foundation 状态区同步。案例见核心认知第 7 条。

### 7. 归档纪律

- 精简时：现行 → archive/，勿删
- 归档区文件禁改（勘误除外）
- 历史方案（旧公理化、旧类比）虽归档但记录其可复活性，勿重复发明

### 8. 验证与沉淀

1. git：项目入 git；有 origin 则 commit + push；敏感内容不入库
2. 重要修改经子代理交叉验证（事实验证 ultrabrain / 概念审查 deep / 质量门 momus，`timeoutMs` 见 skill_creator.md 第五节）
3. 新经验回写：本 skill 或项目 foundation.md 之「风险提示」区
4. LaTeX 改毕用 tectonic 重编译（中文/不兼容则 xelatex），验证 PDF 生成

## 输出格式

体检报告（audit 模式）结构：

```markdown
# 论文项目体检报告（YYYY-MM-DD）
## 一、核心文件清单（现行区）
| 文件 | 角色 | 状态 |
## 二、归档区概况
（文件数、子目录、最近归档项）
## 三、任务状态
（todo 分层摘要 + 最近完成项）
## 四、发现的问题
| # | 问题 | 严重度 | 建议模式 |
## 五、术语与编号一致性
（grep 结果 + 漂移清单）
```

todo 更新：勾选完成项并注日期；新增问题入「已知问题」区。

勘误记录：见执行流程第 6 步格式。

## 注意事项

- **分工边界**：本 skill 管项目结构与纪律。LaTeX 排版编译 → `latex-academic-writing-assist.md`；草稿语言审查 → `paper_assist.md`；bib key 命名 → `bib_key_naming.md`；功能性文档写作规范 → `technical-writing-standard.md`
- **修改纪律**：现行文件用 `edit` 精确改，禁 `write` 覆写整个文件
- **编号漂移**（最易踩坑）：tex 自动编号 + 中途插入 → 后续编号全体 +1。防护三则——新增定义追加到尾部；跨文档引用以名称+章节为主；体检时逐条核对 tex 内部引用
- **同名异实**：跨传统引用概念时，先辨明所指（AE 层级 ≠ A/E 系统）；归属核对以本地藏书目录为第一证据源
- **AI 协作**：子代理验证聚焦数字、引文、归属、方向性断言四类；日常语言润色不必兴师动众
