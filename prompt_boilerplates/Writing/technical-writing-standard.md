# 文档写作规范（ASD-STE100 适配版）

## 背景：什么是 ASD-STE100

**ASD-STE100 Simplified Technical English（简化技术英语，简称 STE）**是技术文档写作的国际标准，由欧洲航空航天与国防工业协会（ASD）拥有和维护，前身是 1979 年启动的 AECMA Simplified English，现行版本为 **Issue 9**。

标准由两部分组成：
1. **Part 1 写作规则**（60 余条，随版本演变）：语法与文体规则
2. **Part 2 受控词典**（约 900 个核准词）：一词一义、一词一词性，基于美式英语

设计目标：让非英语母语的读者（如全球机务人员）无歧义地理解维修手册等技术文档。虽源自航空业，官方明确其原则适用于一切技术文档（被 S1000D 规范引用），且"短句、一句一主题、主动语态"等基本原则可普遍采纳——即使不按词典写作，仅采用这些原则即可显著提升可读性。

## 核心写作规则（完整清单）

> 注：以下为 STE 规则 + 本仓库按中文/脚本场景补充的落地细则的混合清单（场景小节以裁剪版为准）；STE 原标准以官方规范为准。

### 1. 句子
- 每句不超过 20 词
- 一句只表达一个主题/一个想法
- 一段一个主题；段落顺序 = 逻辑顺序

### 2. 指令（程序性文本）
- 一句一个指令
- 用祈使句（命令式）直接开头：`Install the valve.` / `Open the file.`
- 禁止叙述式指令：`The valve must be installed.` ✗ → `Install the valve.` ✓
- 程序用编号步骤列表；列表项结构平行、动词开头

### 3. 语态与时态
- 主动语态优先：A does B
- 描述性文本用主动；被动仅在动作承受者为主角且必要时使用
- 现在时为主；避免 will 将来时；避免 -ing 进行时/动名词（ing 结尾易歧义）
- 不用祈使以外的复杂时态结构

### 4. 词汇
- 一词一义：同义词只保留一个（用 start，不用 begin/commence/initiate）
- 用简单常用词：do 而非 accomplish/achieve
- 术语全文一致，不换说法（同一概念从一而终）
- 避免行话、习语、俚语、含糊词（etc.、and so on）
- 领域术语（technical names）允许，但首次出现时定义、之后一致使用

### 5. 语法细节
- 数字用数字写：5、25，不用 five、twenty-five
- 冠词不省略：a/an/the
- 条件句：关键条件放句首（`If hot oil touches your skin, it can cause burns.`）
- 直接否定：do not；避免双重否定与 not...unless 绕弯
- 避免修饰歧义：不省略必要的 that/which；无悬垂修饰语

### 6. 警告与注意
- 分级：WARNING（人身危险）/ CAUTION（设备损坏）/ NOTE（补充说明）
- 先给警告，再给指令
- 警告语言一旦确定不再改写（法务/安全要求）

### 7. 脚本与程序输出文本（本仓库补充）

脚本/程序通过文本与用户自动化交互（echo、print、Write-Host、日志行、错误提示、交互询问），这些消息是用户唯一能看到的"文档"，同样遵守本规范：

- **短句**：一条消息 ≤ 20 词（中文 ≤ 40 字），一句一个信息
- **指令祈使**：提示用户操作时直接说"要做什么"（"Press Enter to continue."），不用"用户应当..."式叙述
- **术语一致**：同一脚本/程序内同一概念同一措辞（帮助、错误、提示三处必须一致）
- **主动语态、现在时**：避免 will 将来时与 -ing 进行时
- **状态消息**：用固定前缀模板（如 `[OK]` / `[FAIL]` / `[WARN]`），机器可读且人可读
- **错误消息**：先说条件/原因，再说动作（"If the file exists, ..."）；不裸露裸异常堆栈给普通用户
- **数字用数字**：写 5、25，不写 five、twenty-five

## 中文适配（本仓库实际使用）

STE 为英文设计；中文产出套用其**精神**而非字面：
- **短句**：一句一个主题，中文单句控制在 40 字内（对应 20 词）
- **指令祈使**：操作说明直接以动词开头（"打开文件"），不用"文件需要被打开"
- **主动语态优先**：A 做 B，少用"被"
- **术语一致**：同一概念全文同一说法，不换同义词
- **条件前置**：如果...则...，关键条件放句首
- **编号步骤**：程序性内容用编号列表，结构平行
- **数字用数字**：写 5、25，不写五、二十五

## 适用边界（重要）

**✅ 适用（文档/功能性写作）**：
- README、CHANGELOG、CONTEXT、实施计划
- Obsidian 笔记、错题分析笔记
- 试卷题面指令、解析（rationale）、说明文字
- CLI 帮助文本、错误信息、交互提示
- 脚本/程序输出消息（echo、print、Write-Host、日志行、错误提示、交互询问）
- skill 指令文本
- 闪卡文本、学习例句（语言学习材料）

**❌ 豁免（文学/学术/风格类）**：
- 文学创作（小说、诗歌、风格模仿）——完全豁免
- 文学翻译——豁免
- 学术论文——仅采纳"清晰性"子集：短句（≤ 25 词）、术语一致、数字写法、主动语态偏好、一词一义；不套用词典控制与祈使句
- 数学公式、代码、数据表——不受本规范约束

## 附录：逻辑符号——关系词替换（v1.3.0）

> **定位**：逻辑符号用于**替换自然语言中的顺承/逻辑关系词**——「如果…则…/导致/意味着」→ `→`，「并且」→ `∧`，「非」→ `¬`，「必须」→ `□`，「允许/可能」→ `◇`。作用是让读者**一眼识别关系**、不必费力辨认同义表述（leads to / results in / implies / causes 都是 `→`）。**自然语言始终是主体**：句子结构、内容词、示例保持原文，只把关系词换成符号。这是对原有规范的**加强**，不是替代——禁止把句子改写成公式。

### A. 用法规则

1. **只换关系词，不换内容词**：`如果磁盘满，则拒绝写入` → `磁盘满 → 拒绝写入` ✓；但「磁盘」不可写成 `D`（内容词不换）
2. **句子主体不变**：符号嵌在完整句子里，符号前后要能自然朗读；`磁盘满 → 拒绝写入` 可读 ✓，`∀e∈O:e∈P` 不可读 ✗
3. **首次使用给读法**：文首一行图例，或首次出现处括号注释（`→`（如果…则…））
4. **密度克制**：一句最多 1-2 个符号；某段符号过多说明该用表格
5. **能用表格就不用符号**：条件/分级关系列表比符号串更易读

### B. 关系词对照表

| 自然语言（同义族） | 符号 | 例 |
|---|---|---|
| 如果…则… / 导致 / 引起 / 意味着 / 因此 / implies / leads to / results in | → | 磁盘 >90% → 拒绝写入 |
| 并且 / 同时 / 两者都 / both…and | ∧ | 备份 ∧ 校验通过 → 提交 |
| 或者 / 任一 / or | ∨ | A ∨ B 任一满足即可 |
| 不 / 非 / 绝不 / not / never | ¬ | ¬可写 = 不可写 |
| 所有 / 每 / every / all | ∀ | ∀ 消息 ≤ 20 词 |
| 存在 / 有些 / there exists | ∃ | ∃ 未校验记录 → 拒绝 |
| 属于 / 在…中 / is in | ∈ | 状态 ∈ {OK, FAIL} |
| 不属于 / is not in | ∉ | 错误码 ∉ 允许列表 → 告警 |
| 必须 / 强制 / must / mandatory | □ | □ 升级前先备份 |
| 允许 / 可以 / 可能 / may / allowed / possible | ◇ | 缓存 ◇ 可选 |
| 等于 / 相同 / equals | = | 重试次数 = 3 |
| 不等于 / 不同于 / differs from | ≠ | 平均 ≠ 全部 |

### C. 示例（改前 / 改后）

| 改前（纯自然语言） | 改后（关系词替换） |
|---|---|
| 如果磁盘使用率超过 90%，系统将拒绝写入。 | 磁盘使用率 > 90% → 拒绝写入。 |
| 选项包含原文从未提到的元素，因此应该排除。 | 选项包含原文从未提到的元素 → 排除。 |
| If the first noun is "there", a gerund, or source material, eliminate it. | First noun = "there" / a gerund / source material → eliminate. |
| 被动语态仅在动作承受者为主角且必要时使用。 | 仅当承受者为主角 ∧ 必要时，才用被动语态。 |

### D. 反例（禁止——这是公式化，不是关系词替换）

| ✗ 禁止（数学化） | ✓ 允许（词级替换） |
|---|---|
| True = ∀e∈O: e∈P；False = ∃s∈P: O 矛盾于 s | 选项每个元素都在原文中 → True；选项与原文矛盾 → False |
| would have done ⇒ □¬(happened) | 若后文确认事件发生 → would have done 错误 |
| □¬(invent variable ∉ passage) | 绝不引入原文未讨论的变量 |
| Cause = S₁→S₂；Addition = S₁∧S₂ | 原因：后句是前句的结果（S₁ → S₂）；并列：后句只是补充（∧） |

### E. 边界与写法

- **禁用场景**：面向一般大众的文本（CLI 交互、客服文案、试卷题面）不用符号，保持纯自然语言
- **行内用 Unicode 符号**（→ ¬ ∧ ∨ ∀ ∃ ∈ ∉ □ ◇ = ≠）：Obsidian/网页/PDF 均正常渲染
- **LaTeX 仅用于数学公式块**（按 [obsidian_note_generation.md](../Note_Creating/obsidian_note_generation.md) 的数学公式规范）；技术写作正文不用 LaTeX
- **纯文本环境**（终端、电报等）回退自然语言
