# 基于模型的持股分析

## 任务目标

对用户持仓（或候选股）做「模型信号 + 基本面」双轨交叉验证，产出可执行的止损线、入场时机与后续决策。**所有数字必须来自引擎输出、价格数据或公开接口的逻辑计算结果，禁止估算或幻觉数字。**

本 skill 沉淀自 VERSION2.5 生产实战（2026-08-27/28：uv_v11 引擎、sz000166/sz000153/sz000598 实盘分析）。

## 执行流程

### 1. 读取生产数据与引擎输出

- 读 `{project_dir}/results/daily_signal_latest.json`：信号日、slot1/slot2 当选、backups、path_risk（触止损概率/中位回撤/h21 区间/中位持有）、过滤统计
- 读 `{project_dir}/results/trade_state.json`：用户实报持仓（code/entry_price/shares/entry_date）
- 读 `{project_dir}/results/paper_follow_state.json`：模型纸面仓（对比实盘与纸面的执行差）

### 2. 引擎评估个股（复用 stock_forecast.py）

```bash
python3 {project_dir}/scripts/stock_forecast.py --symbol sz000598 --state results/trade_state.json --days 15
```

必取字段：slot1/slot2 分数与**截面排名%**（越小越偏好）、关键因子（rv_21d/pc_resid_rsi/price_pos_252d/ret_126d）、近 N 日轨迹（排名演变）。

### 3. 价格数据与结构（raw 口径）

- 拉实时价：腾讯 `qt.gtimg.cn/q=sz000598`（现价/涨跌/高低/量额）
- 拉日线：`{project_dir}/data/sina_raw/{code}.csv` 尾部 20-30 行——算支撑（近期低点/整数位）、阻力（近期高点）、量能变化（放量/缩量）、除权事件
- **持仓盈亏一律用 raw 价计算**（见注意事项 A1）

### 4. 基本面交叉验证

- 复用 `{finance_dir}` 方法论（fetch_data.py 数据源、analyze.py 指标、report.md 框架）
- 必查项：PE(TTM)/PB/市值/ROE/负债率（腾讯或东财接口）、主业与近期事件（公告/中报窗口/重组/减持/质押）、是否 ST
- 事件驱动信号识别：若模型信号（如 P_C 负漂移）恰逢重大事件（控制权变更/中报），标注「信号本质 = 事件博弈，基本面仅确认壳干净」

### 5. 止损线决策（双轨合成）

止损线 = 协议基线 + 技术修正 + 事件修正，逐项计算并记录公式：

| 层 | 规则 | 计算 |
|---|---|---|
| 协议基线 | 硬止损 -8%、止盈 +20%、时间止损 60 交易日 | `SL = entry × 0.92`，`TP = entry × 1.20` |
| 技术修正 | 关键支撑位（近期低点/平台下沿） | 若 `支撑 < SL` 则维持协议 SL；若 `支撑 > SL` 且距 entry < 8% 则收紧至支撑下方 1-2% |
| 事件修正 | 事件窗口（中报/过户/解禁） | 事件前降仓或收紧；事件落地无雷后恢复 |
| 模型修正 | path_risk 触止损概率 | `p_hit_sl > 50%` → 提示仓位减半；`p_hit_sl < 30%` → 可维持满仓 |

最终输出：止损价、止盈价、时间止损日、仓位建议，每条附计算式与数据来源。

### 6. 入场时机判定（候选股）

- 主信号：信号日收盘版（17:30 后）为准；**盘中预览仅作参考，不得作为执行依据**
- 次日 9:30-9:35 限价单（限价 = 信号日 raw 收盘价）；涨停封死 → 放弃该槽位；14:45 未成交 → 14:50 市价追价
- 加仓判定（已持仓 + 候选）：仅当模型排名改善（排名% 较入场日收窄 ≥50%）且价格未破入场后低点
- 补仓判定：拒绝「价格比成本低即补」；须满足（a）模型排名不劣化 且 （b）价格接近预设金字塔位（如 -4%~-6% 档） 且 （c）无事件利空

### 7. 后续决策量化定义

对每只持仓输出四态决策表（触发条件全部量化）：

| 状态 | 触发条件 |
|---|---|
| 持有 | 收盘价 ∈ (SL, TP) 且持有 < 60 交易日且无事件利空 |
| 减仓 | 事件窗口临近 或 模型排名劣化 > 50% 位 或 p_hit_sl 修正触发 |
| 止盈 | 收盘 ≥ TP 或 触 60 交易日时间止损 |
| 止损 | 收盘 ≤ SL（raw 口径） |

## 输出格式

输出结构化 Markdown 报告，每只股票一节：

```text
## {code} {名称}（{当前价}，{涨跌}）
### 引擎读数（信号日 {date}）
- slot1/slot2 分数与排名%、关键因子、轨迹要点
### 价格结构（raw）
- 支撑/阻力/量能/除权事件
### 基本面（{来源}）
- PE/PB/市值/ROE/负债率 + 事件
### 决策
- 止损 {SL}（= entry×0.92，技术修正 {说明}）
- 止盈 {TP} | 时间止损 {日期}
- 仓位建议 {数量/比例}（依据 {p_hit_sl}）
- 四态决策表
### 数据来源
- 每项数字标注来源（引擎 JSON / sina_raw CSV / 腾讯接口 / 公告）
```

## 注意事项

### A. 踩坑经验（2026-08-27/28 实测）

1. **hfq 与 raw 价格口径**：`feature_cache*.npz` 的 `prices` 是**后复权价**（如 sz000166 显示 7.31，raw 实为 4.56）。持仓盈亏、止损触发、价格上限**一律用 sina_raw CSV 的 raw 价**。用 npz 价算浮盈会得 +60% 假象。
2. **截面排名语义**：stock_forecast 的排名% = 降序分数百分位，**越小越偏好**（0.8% = 全池前 1% = 高度偏好；50% = 中位）。初版曾误读为「越大越偏好」导致结论完全颠倒。
3. **盘中数据 ≠ 收盘数据**：全池盘中快照可构造沙盒预览（须 hfq 行按比例缩放，否则拼接处产生 −38% 假跳变），但**执行决策必须以 17:30 管线收盘版为准**。2026-08-27 沙盒预览（slot1=sz000598/slot2=sz000153）与收盘版一致，方法验证通过。
4. **raw 序列跨除权日**：raw 收益类指标跨除权日会剧变（ret_126d −43% 是真实的，非 bug）；解读时确认窗口是否跨除权/送转。
5. **管线依赖文件缺失**：daily_pipeline 2b 曾引用不存在的 `limit_up_features_v2.npz` 致整条管线 exit（2026-08-27 17:30 无信号）。生产脚本改动后必须 `bash -n` + md5 双端核对 + 手动补跑验证。
6. **模型信号与基本面分离**：P_C 类信号可能捕捉事件博弈（重组/中报），此时基本面只能做「壳干净无雷」确认，不能支撑估值买入。分析报告必须区分「模型信号性质」与「基本面质量」。

### B. 防幻觉铁律

- 每个数字必须可溯源：引擎 JSON 字段名、CSV 行、接口字段、公告原文
- 拉不到的数据写「无法获取」，禁止推算或编造
- 所有计算在报告中留公式（如 `SL = 4.553 × 0.92 = 4.19`）
- 引用历史统计（如 path_risk n=580）必须注明来自 daily_signal_latest.json 的 path_risk 字段
- 不确定的解读标「待验证」

### C. 边界情况

- 停牌股：sina_raw 无当日行 → 持仓按停牌处理，不触发止损
- 候选股涨停：限价买不进 → 放弃，用 backups 递补（递补前检查交集后验警告）
- 数据滞后：raw CSV 落后信号日 → 排除该股并提示同步
- 模型新腿（如 uv_v11 首日）：p_hit_sl 等统计样本小（n<200），置信度降低，仓位建议保守
